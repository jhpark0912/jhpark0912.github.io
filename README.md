# 모바일 청첩장

React + Vite로 만든 모바일 청첩장입니다. GitHub Pages(`https://jhpark0912.github.io/`)로 배포됩니다.

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm run build    # 타입 체크 + 프로덕션 빌드
npm run preview  # 빌드 결과 미리보기 (http://localhost:4173)
```

같은 와이파이의 휴대폰에서 열어보려면 `npm run dev -- --host`로 띄운 뒤, 터미널에 찍히는 `Network:` 주소를 폰 브라우저에 입력하세요.

한 개의 HTML 파일로 묶어 어디서든 열어보려면:

```bash
npm run build && node scripts/build-preview.mjs
```

`preview.html` 하나에 스타일·스크립트·이미지가 모두 인라인되어 나옵니다. 외부 요청이 없으므로 파일을 그대로 열거나 아무 데나 올려도 동작합니다. 다만 Pretendard는 CDN에서 받아오므로 이 파일에서는 시스템 기본 한글 폰트로 대체됩니다.

## 구성

| 섹션 | 내용 |
| --- | --- |
| 인트로 | 이름과 날짜가 떠오르는 오프닝. 커버 사진 로딩 시간을 가려줍니다. 탭하면 건너뜁니다. |
| 커버 | 풀스크린 사진, 스크롤에 따른 완만한 패럴랙스 |
| 초대합니다 | 시 구절 · 인사말 · 양가 혼주 |
| 연락하기 | 신랑/신부 측 아코디언, 전화·문자 버튼 |
| 예식 일정 | 달력 하이라이트 + 실시간 카운트다운 |
| 우리의 순간 | 스와이프 캐러셀 + 전체 화면 라이트박스 |
| 오시는 길 | 카카오맵, 주소 복사, 지도 앱 연결, 교통편 |
| 마음 전하실 곳 | 계좌 아코디언 + 원탭 복사 |
| 참석 여부 | 바텀시트 폼 (Firestore 저장) |
| 축하 메시지 | 방명록 목록·작성·삭제 (Firestore 저장) |
| 공유하기 | 카카오톡 공유, 링크 복사, 시스템 공유 |

모든 섹션은 화면에 처음 들어올 때 한 번만 페이드인하며, `prefers-reduced-motion`이 켜져 있으면 애니메이션 없이 바로 표시됩니다.

인트로와 커버, 마지막 인사를 뺀 나머지 아홉 개 섹션은 [관리자 페이지](#관리자-페이지)에서 순서를 바꾸고 숨길 수 있습니다.

## 아직 비어 있는 정보

아래 항목은 값이 비어 있고, 비어 있는 동안에는 해당 UI가 **표시되지 않습니다**. 잘못된 정보가 노출되는 것보다 낫기 때문입니다.

| 항목 | `wedding.ts` 위치 | 비어 있을 때 |
| --- | --- | --- |
| 계좌번호 | `accounts.groom` / `accounts.bride` | **마음 전하실 곳 섹션 전체가 숨겨짐** |
| 웨딩 사진 | `cover`, `gallery` | 플레이스홀더 이미지 표시 |
| 공유 썸네일 | `public/images/share.jpg` | 카카오톡 공유 카드의 이미지가 빈 채로 나감 |
| 예식장 대표번호 | `venue.tel` | 예식장 전화 링크만 숨겨짐 — **의도적으로 비워 둔 항목** |

형제 서열(`order`)은 전달받지 못해 각각 `아들` / `딸`로 두었습니다. `장남` / `차녀` 등으로 바꾸면 그대로 반영됩니다.

고인이 되신 분은 `motherDeceased` / `fatherDeceased`를 `true`로 두면 이름 앞에 흰 국화가 붙습니다. 현재 신부 어머니(김기자)에 적용되어 있습니다.

연락하기 섹션은 신랑·신부 두 사람만 표시합니다. 번호가 비어 있는 사람은 목록에서 빠지고, 둘 다 비면 섹션 전체가 숨겨집니다.

예식장 좌표(`venue.lat` / `venue.lng`)는 `null`로 두면 카카오 지오코더가 `venue.address`를 실행 시점에 좌표로 변환합니다. 특정 위치를 직접 지정하고 싶을 때만 숫자를 넣으세요.

인사말(`greeting.poem` / `message`)은 일반적인 문구가 들어가 있습니다. 직접 쓰신 글로 교체할 수 있습니다.

## 내용 바꾸기

**보통은 코드를 고칠 필요가 없습니다.** [관리자 페이지](#관리자-페이지)에서 문구·사진·순서를 바꾸고 **게시하기**를 누르면 배포 없이 바로 반영됩니다.

코드로 고치는 쪽은 두 경우에 씁니다. Firebase를 아직 연결하지 않았을 때, 그리고 아무것도 게시되지 않았을 때 보일 **기본값**을 바꿀 때입니다.

`src/data/wedding.ts` 한 파일에 신랑신부·일시·장소·좌표·계좌·사진 목록·인사말이 모두 들어 있습니다. 컴포넌트에는 결혼 정보가 하드코딩되어 있지 않으므로 이 파일만 고치면 됩니다.

날짜는 반드시 `+09:00` 오프셋을 포함해 적어주세요. 해외에서 열어도 한국 기준 날짜와 D-day가 동일하게 보입니다.

실행 시점에는 이 파일의 값 위에 `site/published` 문서의 내용이 한 항목씩 덮어씌워집니다. 관리자 페이지가 건드리지 않은 항목, 형식이 깨진 항목은 이 파일의 값이 그대로 남으므로, 콘솔에서 문서를 잘못 고쳐도 청첩장이 빈 화면이 되지는 않습니다.

`index.html`의 `<title>`과 OpenGraph 태그는 빌드 시점에 정적으로 들어가므로, 데이터를 바꾸면 이곳도 같이 수정해야 공유 카드에 반영됩니다.

## 사진 규격

자리마다 크롭되는 틀이 정해져 있고, 틀과 비율이 다른 사진은 넘치는 쪽이 잘립니다. 아래 비율로 맞추면 잘리는 부분 없이 들어갑니다.

| 자리 | 크롭 비율 | 권장 픽셀 | 표시 크기(430px 컬럼) |
| --- | --- | --- | --- |
| 커버 | 세로, 화면 전체 | 900×1600 (9:16) | 430 × 화면 높이 |
| 신랑신부 사진 | 가로 16:9 | 1400×790 | 430×242, 좌우 풀블리드 |
| 일정 사진 | 세로 4:5 | 1120×1400 | 378×472 |
| 인사 사진 | 세로 4:5 | 1120×1400 | 300×375 |
| 갤러리 | 세로 4:5 | 1120×1400 | 315×394 |
| 공유 썸네일 | 가로 1200×630 | 1200×630 | 카카오톡 카드 |

- **커버는 9:16보다 실제로 더 길쭉합니다.** 프레임이 `100svh`라 폰에서 대략 9:18~9:20이 되므로, 9:16 사진을 넣어도 좌우가 10% 안팎 잘립니다.
- **신랑신부 사진만 가로입니다.** 두 사람을 소개하는 낮은 띠라 세로 사진을 넣으면 위아래가 크게 잘려 얼굴이 날아갑니다. 전신보다 상반신 컷이 맞습니다 — 242px 높이에 전신 2인이면 얼굴이 30px 안팎으로 들어갑니다.
- 비율을 못 맞춘 사진은 관리자 페이지 사진 탭의 **가로 · 세로 막대**로 크롭 기준점(`object-position`)을 옮길 수 있습니다. 저장되는 값은 `GalleryPhoto.focusX` / `focusY`(0~100)이고, 커버만 기본값이 `50 / 30`입니다.
- 사이사이 사진 세 자리에만 **크기 막대**가 추가로 붙습니다. 저장되는 값은 `GalleryPhoto.zoom`(1~2, 기본 1)이고, 렌더링은 `transform: scale()` + `transform-origin`을 `focusX/Y`에 맞춰 적용합니다(`SpotPhoto.module.css`). **1 미만은 허용하지 않습니다** — `object-fit: cover`라 1에서 이미 틀을 채우고 있어, 그보다 줄이면 사진이 더 보이는 게 아니라 틀에 여백이 생깁니다. `siteConfig.ts`의 `scale()`이 1~2로 클램프합니다.
- 관리자 페이지로 올린 사진은 `lib/photos.ts`의 `MAX_EDGE`에 따라 **긴 변이 1400px로 축소**됩니다. 그보다 큰 원본은 의미가 없습니다. 커버만은 이 제한을 피하고 싶다면 `public/images/`에 직접 넣고 `wedding.ts`에서 경로로 지정하세요 — 번들 파일은 축소를 거치지 않습니다.

## 사진 교체

`public/images/`의 파일은 `scripts/make-placeholders.mjs`가 만든 임시 이미지입니다. 실제 사진으로 바꿀 때:

1. 위 표의 비율에 맞춰 `public/images/`에 사진을 넣습니다. WebP 또는 JPEG를 권장합니다.
2. `src/data/wedding.ts`의 `cover`, `gallery` 경로와 `width`/`height`를 실제 값으로 맞춥니다. 비율이 맞아야 캐러셀이 로딩 중에 흔들리지 않습니다.
3. `index.html`의 `<link rel="preload" ... href="/images/cover.svg">` 경로도 새 커버 파일로 바꿉니다.
4. 카카오톡 공유 카드용으로 `public/images/share.jpg`(1200×630 권장)를 추가합니다. **OpenGraph는 SVG를 지원하지 않으므로 이 파일은 반드시 JPEG/PNG여야 합니다.** 없으면 공유 시 썸네일이 비어 보입니다.
5. 준비가 끝나면 `scripts/make-placeholders.mjs`는 지워도 됩니다.

## 카카오 설정

[Kakao Developers](https://developers.kakao.com)에서 애플리케이션을 만들고:

1. **앱 키 → JavaScript 키**를 복사합니다. 지도와 공유가 같은 키를 씁니다.
2. **플랫폼 → Web → 사이트 도메인**에 `https://jhpark0912.github.io`를 등록합니다. 로컬 개발에는 `http://localhost:5173`도 함께 등록하세요.
3. **카카오맵**을 쓰려면 앱 설정에서 지도 서비스를 활성화합니다.

키를 넣지 않아도 사이트는 정상 동작합니다. 지도 자리에는 예식장 이름과 주소가 대신 표시되고, 카카오톡 공유 버튼은 숨겨지며, 링크 복사와 지도 앱 연결 버튼은 그대로 작동합니다.

## Firebase 설정 (관리자 페이지 · 방명록 · 참석 여부)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만듭니다.
2. **Firestore Database**를 생성합니다(프로덕션 모드, 위치는 `asia-northeast3`).
3. **Authentication → Sign-in method**에서 **익명(Anonymous)** 로그인을 켭니다. 이게 꺼져 있으면 방명록 작성과 참석 여부 전송이 실패합니다.
4. **프로젝트 설정 → 내 앱 → 웹 앱**을 추가하고 SDK 구성값을 `.env`(로컬)와 GitHub Secrets(배포)에 넣습니다.
5. 이 저장소의 `firestore.rules` 내용을 **Firestore → 규칙**에 붙여넣고 게시합니다.

### 관리자 페이지

`https://jhpark0912.github.io/admin.html` 에 관리 화면이 있습니다. 청첩장 어디에서도 링크되지 않고 검색에도 잡히지 않지만, 주소만으로 보호되는 건 아니고 실제 권한은 보안 규칙이 강제합니다.

다섯 개의 탭이 있습니다.

| 탭 | 하는 일 |
| --- | --- |
| 내용 | 예식 일시, 신랑·신부와 혼주, 인사말, 예식장과 교통편, 계좌, 참석 여부·방명록 안내 문구, 카카오톡 공유 카드 |
| 사진 | 커버·사이사이·갤러리 사진 업로드·삭제·순서 변경, 크롭 위치 조정 |
| 순서 | 섹션의 순서 바꾸기와 숨기기 |
| 방명록 | 남겨진 축하 메시지 조회·삭제 |
| 참석 여부 | 응답 명단과 집계 조회, 엑셀(CSV) 내려받기 |

쓰려면 Firebase에서 세 가지를 해야 합니다.

1. **Authentication → Sign-in method → 이메일/비밀번호** 사용 설정
2. **Authentication → Users → 사용자 추가** 로 관리자 계정을 만들고, 생성된 **사용자 UID**를 복사
3. **Firestore Database → 데이터** 에서 `admins` 컬렉션을 만들고, **문서 ID를 그 UID로** 하는 빈 문서를 추가

3번이 실제 권한 부여입니다. 규칙이 `admins/{uid}` 문서의 존재 여부로 관리자를 판별하므로, 관리자를 더하거나 빼는 데 규칙을 고칠 필요가 없습니다.

UID를 미리 복사해두지 않았다면 그냥 로그인해 보세요. 권한이 없으면 **등록에 필요한 UID를 화면에 띄워줍니다.** 그 값을 문서 ID로 써서 `admins` 문서를 만들고 다시 로그인하면 됩니다.

참석 응답은 이름과 연락처가 담기므로 일반 방문자에게는 읽기가 완전히 차단되어 있고, 관리자만 볼 수 있습니다.

### 임시저장과 게시하기

내용·사진·순서 탭의 변경은 **두 단계**를 거칩니다.

- **임시저장** — 아무도 보지 못하는 초안(`site/draft`)에 저장합니다. 하객 화면은 그대로입니다.
- **게시하기** — 초안을 하객이 보는 문서(`site/published`)로 복사합니다. 이 순간부터 반영됩니다.

나눠 둔 이유는, 하객이 청첩장을 읽고 있는 동안에도 마음 놓고 고칠 수 있게 하기 위해서입니다. 절반만 고친 문구가 남에게 보이는 일이 없습니다.

임시저장한 뒤에는 **미리보기**로 초안 상태의 청첩장을 새 탭에서 열어볼 수 있습니다(`/?preview=draft`). 관리자로 로그인한 브라우저에서만 열리고, 다른 사람이 같은 주소를 입력하면 게시된 청첩장이 나옵니다.

저장하지 않고 탭을 닫으려 하면 브라우저가 한 번 물어봅니다.

### 사진에 대해

이 프로젝트에는 Firebase Storage 버킷이 없어(지금은 결제 정보 등록이 필요합니다) 올린 사진은 **Firestore 문서 하나에 한 장씩** 들어갑니다. 그래서 브라우저가 업로드 직전에 사진을 줄입니다.

- 긴 변을 최대 **1400px** 로 맞추고, 한 장이 약 **250KB** 아래로 들어갈 때까지 JPEG 품질을 낮춥니다. 요즘 휴대폰 화면에서는 원본과 구별하기 어렵습니다.
- 사진 탭에 올린 사진의 총 용량이 표시됩니다. 하객이 그만큼을 내려받아야 하므로, 갤러리는 8~12장 정도가 적당합니다.
- 사진은 **고른 즉시** 저장됩니다. 순서 변경·설명 수정·삭제는 그 뒤로 용량이 들지 않습니다.
- 갤러리에서 뺀 사진은 곧바로 지워지지 않고, **게시하기** 시점에 아무 데서도 쓰이지 않는 것만 정리됩니다. 아직 옛 버전을 보고 있는 하객의 사진이 도중에 깨지지 않게 하기 위해서입니다.

`public/images/`에 들어 있는 기본 사진은 그대로 두어도 됩니다. 관리자 페이지에서 올린 사진과 섞여 있어도 정상 동작합니다.

### 삭제 권한에 대해

방명록 글쓴이는 익명 로그인 uid로 식별되고, 보안 규칙이 그 uid를 확인해 **본인이 쓴 글만** 삭제할 수 있게 합니다. 비밀번호를 따로 받지 않는 대신, 브라우저 저장소를 지우거나 다른 기기에서 열면 이전에 쓴 글을 지울 수 없습니다. 그런 요청이 오면 Firebase 콘솔에서 직접 삭제하시면 됩니다.

참석 여부 응답은 이름과 연락처가 담기므로 규칙에서 관리자 외의 **읽기를 완전히 막아** 두었습니다. 관리자 페이지의 참석 여부 탭에서 명단과 집계를 보고, 필요하면 엑셀로 내려받을 수 있습니다.

### 설정하지 않으면

`VITE_FIREBASE_*` 값이 하나라도 비어 있으면 모든 저장이 브라우저 `localStorage`로 가는 연습 모드로 동작합니다. 방명록·참석 여부는 물론 관리자 페이지도 로그인 없이 열리고, 화면과 흐름은 실제와 똑같습니다.

이 모드에서 입력한 내용은 **그 브라우저 밖으로 나가지 않고, Firebase를 연결해도 옮겨지지 않습니다.** 실제 청첩장을 돌리기 전에 반드시 Firebase를 연결하고, 내용은 연결한 뒤에 다시 입력하세요.

## 환경 변수

`.env.example`을 `.env`로 복사해 로컬 값을 채웁니다. 배포용으로는 저장소 **Settings → Secrets and variables → Actions**에 같은 이름으로 등록하면 워크플로가 빌드 시 주입합니다.

`VITE_*` 값은 빌드 결과 자바스크립트에 그대로 포함되어 공개됩니다. 이 키들은 원래 그런 용도이며(카카오는 도메인, Firebase는 보안 규칙으로 보호됩니다), 비밀로 지켜야 하는 값은 넣지 마세요.

## 배포

`main` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이 빌드해 GitHub Pages로 올립니다. 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 설정해야 합니다.
